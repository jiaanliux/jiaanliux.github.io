RiskScape × AI Systems — Technical Notes

This companion belongs to visual-architecture.html. It contains the explanations intentionally removed from the visual presentation. This is a code-level integration proposal, not a claim that the three systems have already been deployed inside RiskScape.

1. Native RiskScape extension surfaces

A. No engine changes: CLI / model parameters

  • Official call: riskscape model run damage-by-region -p 'analysis.function=Probability_of_Collapse'.
  • engine/app/src/main/java/nz/org/riskscape/engine/cli/model/RunCommand.java: RunCommand.doCommand(Project) retrieves the model, updates parameters, realizes its pipeline and calls CliPipelineRunner.run(...).
  • .../BaseModelRunCommand.java: supports -p / --param / --parameter and --parameters file.
  • .../BatchCommand.java: accepts --vary-parameter and --vary-input for many model runs.
  • This is the fastest and least invasive interface for Aipelago. It is not a REST API.

B. Add risk functions through RiskScape configuration

  • A [function] registered as framework=cpython can provide a Python implementation of a mathematically defined vulnerability or loss function.
  • plugin/cpython/.../CPythonFunction.java in the public 1.13 source mirror: implementation runs Python in a separate process, serializes arguments, deserializes results, and records runtime metrics. This is an implementation observation, not a guaranteed Java ABI for current 1.14.
  • Model configuration parameter analysis.function (from official Samoa example) switches between damage functions.
  • Proposed ML insertion: (hazard intensity, construction type, asset metadata) → calibrated probability of damage state or expected loss ratio. Model validation remains independent of the interface.

C. Customize the pipeline or engine

  • DefaultPipelineRealizer: builds an executable dataflow from DSL steps, resolves dependencies and types.
  • SchedulerBasedExecutor: schedules and executes linked steps.
  • SampleCoverageAtCentroid, SampleIntersections: spatial sampling routines; selected method changes scientific semantics.
  • SaveSinkConstructor: output sink construction.
  • Java RiskscapeFunction/FunctionProvider extension is possible at source level, but would entail compatibility and maintenance considerations; it is not our first pilot.

2. Aipelago: actually executable first connection

Existing Aipelago code (verified in repository):

  • src/aipelago/kernel/tool/registry.py: ToolRegistry.register(definition, handler, owner_agent=..., scoped=...); register_from_manifest(...) resolves handler modules.
  • src/aipelago/kernel/tool/schema.py: validate_args, validate_output and schema_for_tool for typed tool calls.
  • src/aipelago/kernel/runtime/runtime.py: coordination of model calls, tool exposure, state and run lifecycle.
  • src/aipelago/kernel/state/service.py: state service.
  • src/aipelago/kernel/trajectory/recorder.py: TrajectoryRecorder.record keeps ordered run events and offloads oversized payloads.

New code required: riskscape_tool.py async handler that invokes a RiskScape process adapter. A bridge prototype already exists in the previous code-level integration package; it has only been tested with a synthetic CLI fixture, not end-to-end in Aipelago.

# Schematic contract, NOT a pre-existing Aipelago handler.
async def riskscape_run(model: str, params: dict[str, str]) -> dict:
    # validate model and params against an explicit allowlist
    # run subprocess with shell=False, cwd=approved_project_path
    # check exit status, capture artifact manifest and hashes
    # return structured JSON so the runtime can examine follow-ups
    ...

A minimal data contract:

{"tool": "riskscape_run", "model": "damage-by-region", "parameters": {"analysis.function": "Probability_of_Collapse"}}

Output: {run_id, command, exit_code, stdout_path, stderr_path, artifacts:[{path, sha256}], summary}. Agent context should summarize artifacts rather than embed huge raster or CSV blobs. The harness must expose the handler as a tool with appropriate effects and resource policies. A good harness expands what an LLM can actually do; policies, recovery and monitoring are enabling infrastructure, not its core research claim.

Testing: manual baseline vs agentic task suite: correct models chosen; correct result interpretation; scenario comparisons; tool failures/recovery; intervention rate; time/cost per completed investigation.

3. Tessera: do not mistake model output for observations

Existing code:

  • src/tessera/ingest.py: adapter_iter('jsonl', source_uri) yields records; IngestRecipe maps fields and filters.
  • src/tessera/engine.py: multi-stage map/fold workflow and explicit StageOutcome with failure/cost/latency semantics.
  • src/tessera/calibration.py: create_label_sample builds human-reference samples (with inclusion probabilities for stratified sampling), enabling design-based measurement.

New adapter: independently sourced field/insurance/inspection reports → standardized JSONL with event/asset/region identifiers, timestamps, evidence source and damage codes. Then Tessera's workflow extracts and calibrates observations. A separate compare_evidence.py joins calibrated observations to RiskScape output by carefully matched asset/event keys, reporting match rates and uncertainty.

Data flow: reports.jsonl → adapter_iter → Recipe / engine.Stage → create_label_sample → observations.csv + event-impact.csv → new comparison. Do not take RiskScape's output and call it human ground truth. A successfully parsed report is not automatically a verified measurement.

Testing: human-coded agreement, missing/abstain reporting, matching coverage, confidence intervals for calibrated estimates, failure-mode audits. Tessera validates text-derived measurements, not tsunami hydrodynamic equations.

4. UrbanAgents: infrastructure consequence → people and decisions

Existing code:

  • world/environment.py: CityMap(pois_source=...) supports an in-memory POI inventory; CityMap holds a networkx street graph and POIs.
  • harness/l6_orchestration/model.py: UrbanModel is a Mesa 3 model; agent decisions run with async def astep() and arun(); the synchronous step() is a no-op guard, so it must not be presented as the actual model execution interface.
  • abm/a3_calibration/sweep.py: scenario sweeps and aggregate for KPIs across seeds.
  • harness/l7_session/manifest.py: run metadata.

New code required: asset_to_network.py maps RiskScape output geometries / asset IDs to street-graph edges and service POIs. apply_disruptions(...) must be implemented to update route availability, service capacity and fallback access. Only then can await model.astep() advance the resulting agents through altered environment states.

Example conceptual input:

{"event_id":"quake_01","asset_id":"road_57","edge_id":99101,"functionality":0,"start_time":0,"recovery_time":48}

The current Samoa damage-by-region demonstration summarizes building damage and supplies no verified road closures or hospital capacity losses. It cannot directly support an empirically meaningful transport scenario. For the real pilot, first obtain an infrastructure exposure layer and usable vulnerability/disruption assumptions, and then map those outputs into a city-specific environment.

Testing: graph connectivity, time-to-hospital, shelter access, intervention effectiveness, sensitivity across seeds, and comparison with observed behavioural/network patterns. Plausible LLM-generated behaviours are hypotheses, not automatically validated predictions.

5. Why the three systems are complementary

  • Aipelago: an LLM's effective capability to operate and investigate the modelling environment through tools, state, context, feedback and long-horizon orchestration. The harness can sometimes make a smaller model more capable at a complex task than a larger model with inadequate tools and state.
  • Tessera: a research-grade measurement workflow for independently sourced unstructured evidence and calibrated aggregate claims.
  • UrbanAgents: a downstream behavioural simulation investigating human/organisational consequences that asset-level damage accounting alone typically cannot estimate.

Each has a different evaluation standard. A model with tool access is not automatically a valid scientific predictor. A text extraction system is not a physics validator. A simulated policy response needs empirical constraints.

6. Licensing, access, provenance

The RiskScape public source mirror reviewed here identifies the engine as AGPLv3 and emphasizes research-use restrictions in its file headers. Verify the currently distributed license and discuss obligations before embedding or modifying source in a hosted service. The quickest proposed integrations avoid an engine fork and invoke the existing CLI and function framework.
